# AgentProvenance v0.7.2

v0.7.2 hardens portable evidence production and outbound-data investigation.
It validates the same provenance semantics across local process capture and an
externally scheduled Kubernetes Pod, while keeping the core graph and storage
model substrate-neutral.

## Highlights

- A filtered Kubernetes informer maintains cgroup bindings across container
  restart and Pod deletion.
- One node sensor observes multiple workloads; bounded spool, backpressure,
  drop accounting, producer health, and a measured 100k-event baseline define
  the single-node scale boundary.
- A live local/K8s parity gate runs the same workload through both profiles.
  Both graphs verify with zero errors and warnings and share canonical command,
  runtime-event, and process-event semantics.
- Outbound Data Surfaces unify sensitive context egress, source bundle upload,
  and third-party behavioral telemetry into queryable evidence with risk and
  response links.
- The Grok CLI scenario ships replayable evidence for three distinct outbound
  data routes rather than collapsing them into one generic egress alert.
- Passive kernel events now connect to PID-derived process nodes without
  requiring an application process ID.

## Capability honesty

Producer Profiles now expose `validated` or `planned` status. `local-record` and
`k8s-daemonset` are validated. `microvm-guest-init` remains visible as the next
portability target but reports no available layer coverage and zero scope
confidence until an in-guest runner and live KVM acceptance exist.

The central evidence service remains a documented future architecture. This
release does not claim multi-tenancy, cluster scheduling, billing, operator HA,
or a production distributed control plane.
